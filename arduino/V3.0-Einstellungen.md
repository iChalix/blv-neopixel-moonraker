# Arduino-Seite: NeoPixelBLVmgn V3.0 mit Klipper

Fuer diese Variante muss die Middleware umgestellt werden - Standard ist
V4.x:

```ini
[printer]
sketch_version = 3.0
```

Der Sketch bleibt **unveraendert** - die Middleware spricht genau das
Protokoll, das V3.0 erwartet. Angepasst werden nur die `#define`-Zeilen im
Block "User-Config" von `NeoPixel_BLV.ino`.

Sketch holen:

```bash
wget https://github.com/mule1972/NeoPixelBLVmgn/archive/refs/tags/V3.0.tar.gz
```

Benoetigte Bibliothek: **Adafruit NeoPixel** >= 1.2.3 (Arduino IDE ->
Bibliotheksverwalter). Weitere Abhaengigkeiten hat V3.0 nicht.

## Passt bereits zu 3 Ringen mit je 16 LEDs

Die Werkseinstellung von V3.0 trifft genau diesen Aufbau:

| Ring | Arduino-Pin | `DisplayPrinterObject` | Anzeige |
|------|-------------|------------------------|---------|
| NeoPixel1 | 7 | `99` | Druckerstatus + Fortschritt |
| NeoPixel2 | 6 | `0`  | Heizbett |
| NeoPixel3 | 8 | `1`  | Hotend |
| NeoPixel4-6 | - | - | `Active false` |

`NeoPixelN_LEDs 16` und `NeoPixelN_Type NEO_GRB + NEO_KHZ800` stimmen fuer
die Ringe aus der BLV-Stueckliste.

## Empfohlene Anpassungen

```c
// 0-112 C auf 16 LEDs - passt besser zu einem Klipper-Heizbett (max 110 C)
#define Heater0_Scale 7     // Werkseinstellung 10 = Bereich bis 160 C

// 0-320 C auf 16 LEDs - fuer ein 300-C-Hotend unveraendert gut
#define Heater1_Scale 20

// Werkseinstellung 8 ist sehr dunkel; 40-80 ist im Raum gut sichtbar
#define NeoPixel1_Brightness 40
#define NeoPixel2_Brightness 40
#define NeoPixel3_Brightness 40

// Startpunkt der Grafik drehen, falls der Ring schief montiert ist
#define NeoPixel2_PixelOffset 0    // positiv = im Uhrzeigersinn
```

`Scale` = Temperaturbereich / Anzahl LEDs. Die erste LED leuchtet ab
`TempOffset`; mit `NeoPixelN_TempOffset 20.0` beginnt die Skala erst bei
Raumtemperatur, dann gilt `Scale = (Max - 20) / 16`.

## Verdrahtung Raspberry Pi <-> Arduino

V3.0 **hoert nur zu** und fragt nichts ab. Es wird also nur eine
Datenrichtung gebraucht: Pi TX -> Arduino RX.

**Variante A - USB (empfohlen):** Arduino Uno/Nano per USB-Kabel an den Pi.
Nichts weiter zu tun, die Middleware findet das Geraet unter
`/dev/serial/by-id/...`. Kein Level-Shifter, kein PanelDue, kein Duet.

**Variante B - GPIO-UART** (z. B. Pro Mini ohne USB):

| Raspberry Pi | Arduino |
|--------------|---------|
| GPIO14 / TXD (Pin 8) | RX |
| GND (Pin 6) | GND |

Pi-TX mit 3,3 V am 5-V-Eingang des Arduino ist unproblematisch (High-Pegel
wird ab ca. 3,0 V erkannt). Die Rueckrichtung Arduino-TX -> Pi-RX wird
**nicht** gebraucht und sollte ohne Spannungsteiler auch nicht verbunden
werden. Dann in der Konfiguration `port = /dev/serial0` setzen und die
serielle Konsole des Pi abschalten (`sudo raspi-config` ->
Interface Options -> Serial Port -> Login shell: nein, Hardware: ja).

Die 5-V-Versorgung der Ringe gehoert an ein eigenes Netzteil mit gemeinsamer
Masse - 48 LEDs koennen bei voller Helligkeit ueber 2 A ziehen, das haelt
weder der Pi noch der Arduino aus.

## Debug-Build

Mit `DEBUGLEVEL1_ACTIVE` schreibt der Sketch auf einem Uno/Nano auf dieselbe
USB-Schnittstelle, auf der er die Daten erwartet. Das stoert den Betrieb
nicht, erzeugt aber Last; `log_incoming = true` in der Middleware-Konfiguration
schreibt diese Zeilen ins Journal.
